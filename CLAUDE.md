# CLAUDE.md

Guidance for AI coding assistants working in this repository.

## Overview

**Multi-property interactive map**: `/` is the single-engine MapLibre atlas (`v2/`, see the V2 section) and `/classic` is the original Leaflet app; both serve several properties, each with its own boundary, project zones, panels, and photo galleries. Every property module carries its `apn` and `county` (FIPS) so the county record anchors by parcel, not by centroid; **`docs/property-intake.md` is the standing rule for adding any parcel, in or out of Ventura County**. Current properties: `howard` (1320 Baldwin Rd, Ojai — 13 proposal zones), `sulphur-mountain` (Eco-Village — 18 zones, V1 data from `SacredRebel/EcoVillage-map`), `keris-property` (3 zones), `chers-property` (2 zones), and `black-mountain-ranch` (63 real county parcels drawn as lot territories + 6 Lemuria vision zones).

## Architecture

- **`properties/*.js`** — one module per property: `{ id, name, shortLabel, labelChip, center, zoom, footerTitle, footerInfo[], cta { heading, paragraph, contacts[], buttons[] }, panel { title, html }, boundary[], zones[], lots?[], lotStyle? }`. Adding a property = new module + import + append to `PROPERTIES` in server-complete.js.
- **`server-complete.js`** — Express + whole frontend in a template literal. `PROPERTIES` array is injected via the `PROPERTIES_PLACEHOLDER` token (JSON). Aggregates `PROJECT_ZONES` / `PERMANENT_PROPERTY_LINES` feed `/api/health` and `/api/project-zones`.
- **Frontend flow:** map starts at `fitBounds` of all boundaries (overview). Below zoom 13.5 the `#map` div gets `.overview-mode`: per-property **label chips** show (click → flyTo property). Zone markers are shown per property — visible once `zoom >= thatProperty.zoom - 2.5` (`updateMarkerScale`), so a huge ranch shows icons while a small neighbor's stay tucked. Each property renders 3 stacked polylines (glow + animated rainbow + 30px invisible hit line); boundary click → `openPropertyPanel(propId)` which injects `prop.panel.html` and calls `loadPropertyImages(propId)`.
- **🌍 3D terrain mode (V0.13):** `#earth-toggle` (under the mode pill) opens a fullscreen MapLibre GL overlay (`#earth3d`): Esri World Imagery draped over AWS terrarium elevation (`setTerrain`, exaggeration 1.35, maxPitch 80), free/keyless sources. MapLibre 4.7.1 lazy-loads from unpkg on first open; the GL map is destroyed on exit. Rebuilt each open, so it inherits the Current/Vision state: zone markers filter via `window.zoneVisibleInMode`, names via `window.zoneView`, chips honor `visionLabelChip`. Property boundaries render as gold-glow + violet lines, ranch lots as thin white plat lines; chips fly cinematically (`flyTo` pitch 62). 2D map got Google-Earth-feel physics: `zoomSnap 0.25`, long parabolic `flyTo`/`flyToBounds` flights, glide inertia. **V0.14 gesture bridge (one connected map):** middle-mouse-hold-drag on the 2D map (or a parallel two-finger drag on touch — spread change < 45px, |dy| > 38px) opens 3D and the SAME drag keeps driving pitch/bearing — deltas accumulate in `earthPendPitch/Bearing` until GL `load` fires (`earthReady`), then apply live at 0.35°/px; middle-drag orbits inside 3D too (canvas `mousedown` button 1 → shared window-level move handler); `close3D()` hands the camera back (`map.setView(center, glZoom+1)`); gestures are suppressed while `window.positionEditActive`. `#earth3d-gearth` opens the exact current camera in Google Earth web (`earth.google.com/web/@lat,lng,0a,DISTd,35y,Hh,Tt,0r`, no API key). `window.earth3dRef` exposes the GL map for tests. **V0.15 globe + portals:** MapLibre 5.24.0 with `projection: {type:'globe'}` — zooming out curves the map into a planet in space (CSS starfield `#earth3d-stars` under the transparent-space GL canvas, atmosphere halo via style `sky` with `atmosphere-blend` fading by z11; terrain confirmed working WITH globe; the one benign console warning is `calculateFogMatrix is not supported on globe projection`). ## V2 — the single-engine rebuild (`/v2`, since V0.26)

`docs/engine-blueprint.md` is the spec. **`v2/`** is a Vite + TypeScript app on **MapLibre GL 5.24 only** — 2D and 3D are the same scene (2D = pitch 0), so there is one coordinate pipeline and one place a positioning bug could live. `cd v2 && npm install && npm run build` type-checks (`tsc --noEmit`) and writes the bundle to **`public/v2/`**, which is COMMITTED (Vercel runs no build step) and served by the classic Express app: `app.use('/v2', express.static(...))` with immutable caching for `assets/`, plus `GET /api/properties` (the `PROPERTIES` array, positions applied). `vercel.json` carries `includeFiles: ["public/v2/**", "data/**"]` so the function bundle contains them. Glyphs are self-hosted (`v2/public/fonts/Open Sans Semibold/*.pbf`, copied into the build) — no dependency on the MapLibre demo server.

## Operating the atlas

- **Env vars on Vercel** (project `howard-property-dev`): `EDIT_PIN` (the shared PIN every write checks) and `GITHUB_TOKEN` (fine-grained PAT, *Contents: read and write* on this repo only; `GITHUB_REPO` overrides the slug). With both set, `/api/health` says `writes: configured`; the editor's 🔒 Save, the shared research list and the photo / PDF uploads all commit to `main`. Without them everything still works read-only and each client keeps its own local copy.
- **Editing:** open `/?edit=1` once in a browser (`/classic?edit=1` for the Leaflet page) — the ⚙ position editor, `P`, and the *＋ add photos* / *＋ add document* buttons on property and zone cards appear and stay until `?edit=0`. The PIN is asked once and remembered (`localStorage.ojaiMapEditPin`, cleared on a 401).
- **Research list:** ☆ on any record saves the parcel; with the PIN stored every save syncs to `data/research.json`, and every visitor's atlas merges the shared list at boot. The Research tab's ☁ pill shows the state and offers *enter the PIN to share yours* when the list is local only.
- **Title evidence:** buy a property report for the parcel (PropertyChecker works today), open the parcel in editor mode, *＋ import a property report (PDF)* in the Ownership & title section. The evidence (never the PDF, never the residents list) lands in `data/title/<apn10>.json` and the record re-resolves owner-first with every row dated. A report older than a year is flagged — re-order it before an offer. `REGRID_TOKEN` (optional) turns on the live Regrid rows.
- **Tests:** `npm test` from the root (see V0.31). Run it after every change to the server, the classic page or the atlas; the served-JS gate for the classic page stays a separate step.
- **Deploys:** every push to `main` that touches code builds on Vercel; data-only commits (research, uploads, positions) are skipped by `scripts/vercel-ignore.sh`. The warm action then pre-resolves the records and pre-bakes the tiles — check the Actions tab if the first visit after a deploy feels cold.

## Key gotchas

- Frontend lives in a template literal — keep `\${...}` / `` \` `` escaping intact; the injection token is exactly `PROPERTIES_PLACEHOLDER`.
- Boundary segments per property must chain (segment N's last coord = segment N+1's first); client stitches and closes each loop.
- `preferCanvas: true` — boundary/circle vector layers are canvas-rendered (no per-path CSS), zone markers + label chips are DOM divIcons.
- `properties/*.js` panel `html` strings are injected into the panel verbatim — plain string-concat HTML, no `<script>` tags allowed (would break the JSON-in-`<script>` injection).
- Vercel: git-connected project `howard-property-dev` auto-deploys `main`; `/images/*` 302s to THIS repo's raw URLs (for future Howard photos).
- `images/` is the photo-upload tree (`images/<property>/<zone>/{current,vision}/`, property gallery = `images/<property>/property/current/`); new files must be listed in `image-urls.js` to show up.
- After ANY server/frontend patch, run the served-page check: boot the server, curl `/classic`, extract the inline `<script>`, `node --check` it — `node --check server-complete.js` alone does NOT parse the embedded frontend.
